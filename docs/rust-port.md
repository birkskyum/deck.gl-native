# deck.gl-native Rust port: design notes

This document records the decisions behind the 2026 Rust rewrite so that they can be revisited
deliberately rather than rediscovered.

## Destination

A native deck.gl renderer for native hardware (mobile and desktop GPUs) that

- reuses deck.gl's own WGSL shaders and matches its rendering, layer by layer,
- takes Apache Arrow and GeoArrow data without per-row callbacks,
- draws into a render pass owned by a host, so that a basemap renderer such as maplibre-native
  can interleave deck layers with its own drawing and share its depth buffer.

## Decisions so far

**Rust on wgpu, not the 2020 C++ on dawn.** The C++ prototype targets a dawn API from spring
2020 that no longer exists (pre-WGSL, GLSL through shaderc), ships x64-only prebuilt
dependencies and is stale against deck.gl 9. Every GPU call and every shader needed rewriting
anyway. Cargo replaces the vcpkg, depot_tools and gn pipeline, cross-compiles to iOS and
Android, and wgpu exposes its hal layer for importing a host's Metal or Vulkan textures. The
C++ tree stays in `cpp/` as a design reference.

**Port deck.gl 9, not the C++ code.** Module names, class names and even file names follow the
JavaScript packages (`@math.gl/web-mercator`, `@luma.gl/core`, `@deck.gl/core`,
`@deck.gl/layers`) so the two code bases can be read side by side. The C++ prototype's layout
was the same idea applied to deck.gl 8.

**Shaders are deck.gl's WGSL, included verbatim.** `project`, `project32`, `picking`, the
`geometry`, `color` and `layer` modules, luma.gl's `lighting` and `gouraudMaterial`, and the
three layer shaders are copied from deck.gl 9.4 with only their generated headers expanded and
`@binding(auto)` resolved. Uniform block layouts are read back from the assembled WGSL with
naga, so there are no hand-maintained `#[repr(C)]` mirrors to drift out of sync.

**Arrow first.** `LayerData` wraps an Arrow `RecordBatch`; an `Accessor` is a constant, a
column name, or a function of the row index. Column accessors read Arrow buffers directly,
including GeoArrow polygon layouts. Function accessors exist for convenience and small data.
Data compares by column identity, so sending the same batch again costs nothing, and
`LayerData::with_changed_rows` names the rows that differ from the last update: the
`AttributeManager` writes those rows in place and grows its buffers with headroom when rows
are appended, so streaming appends and per row edits do not rebuild every attribute.

**fp64 as hi/lo f32 pairs.** Positions are split the way deck.gl does for `fp64` attributes,
and the viewport switches to auto-offset mode above zoom 12, so precision matches deck.gl JS on
WebGPU.

**Viewport math in f64.** `math-gl` ports `@math.gl/web-mercator` with `glam` doubles and is
tested against values generated by the JavaScript implementation.

**The host owns the frame.** `Deck::draw` encodes into a caller-provided `wgpu::RenderPass`.
`Deck::render` is a convenience that begins a pass on caller-provided texture views. Nothing
in the core knows about windows or surfaces.

**Host interop through wgpu's hal layer, on the host's queue.** For maplibre-native's Metal
backend, `deck-gl-ffi` adopts the host's `MTLDevice` and `MTLCommandQueue` and wraps the
host's drawable and depth textures without copying. The host commits its frame, deck submits
on the same queue, the host presents. See [maplibre-native.md](maplibre-native.md). The camera
sync ports `@deck.gl/mapbox`'s `getViewport`, including maplibre's near and far planes.

## Not yet specified

- **maplibre-native WebGPU backends.** With Dawn or wgpu-native the `WGPUDevice` could be
  shared outright, but that requires building deck.gl-native against `webgpu.h` rather than
  the `wgpu` crate. Undecided.
- **Where the host hook lives.** The demo patches the GLFW app. A proper home is a custom
  layer type in maplibre-native core so the overlay can sit at any position in the style's
  layer order, and so iOS and Android get it for free.
- **Bindings.** A C ABI plus Swift and Kotlin bindings (cbindgen or UniFFI) for embedding in
  mobile apps.
- **JSON API parity.** deck.gl's JSON layer descriptions are the "common API" across
  implementations. Golden-image tests that render the same JSON in JS and native would keep
  the two aligned.
- **Picking, transitions, more layers.** Picking uniforms are wired but no picking pass
  exists. Path, polygon, GeoJSON, icon and text layers all have WGSL in deck.gl 9 and follow
  the same recipe as the three ported layers.

## Out of scope for now

- Globe projection and orthographic views.
- WebGL fallback: WebGPU only, through wgpu's Metal, Vulkan, DX12 and GL backends.
- Anything the JavaScript deck.gl is better placed to do in a browser.
